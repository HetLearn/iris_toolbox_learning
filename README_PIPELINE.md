# iris_toolbox_learning: handoff

## 1. Purpose
`hetlearn`, a MATLAB wrapper toolbox around IRIS (20230622) for forecasts and scenarios
under heterogeneous expectations: rational agents and adaptive learners (constant-gain RLS)
whose population shares switch on forecast performance, following Özden (2025, IJCB 21(1)).
The first model in the portfolio is the Smets-Wouters (2007) model re-estimated on
1966Q1-2026Q2 data (Dynare mode `swX1` from `Desktop/ucur-dsge/sw07-extended`). The
first applications are risk scenarios around the 2022Q2 inflation peak. For the user.
**How to use it** (what you provide, which files you edit, every option, worked examples):
`docs/USER_GUIDE.md`. Keep it in step with `hetlearn.defaults` when options change.
**Repository:** https://github.com/tolgaozden/iris_toolbox_learning (private, branch `main`),
started 2026-10-18: one file per commit, authored by the user only (no co-author lines), each
message explaining the file. Outputs, caches and `archive/` are ignored (`.gitignore`).

## 5. Conventions & gotchas
- Design contract: `docs/DESIGN.md`. Feature register (what is configurable, what was added): `docs/FEATURES.md`.
- MATLAB batch: `& "C:\Program Files\MATLAB\R2025a\bin\matlab.exe" -batch "..." -logfile log.txt` from PowerShell.
- Copy/move files on OneDrive paths with PowerShell, never Git Bash `cp`/`mv`.
- IRIS `solve` returns a `solve.StabilityFlag`; use `hasSucceeded(flag)`.
- Nested `!substitutions` and `!if` toggles inside declaration blocks work in IRIS 20230622 (tested 2026-10-17).
- IRIS 20230622 accepts only `%` and `%{ %}` comments and `x{+k}`/`x(+k)` subscripts; `//`, `/* */`, `x[+k]`, `x{t+k}` fail. The generator converts them; the collapse test then uses `generated/<name>_norm.model`.
- IRIS `simulate` anticipates all shocks by default; pass `'anticipate', false` for multi-period unanticipated runs.
- `srf` output includes presample rows that depend on the max lag; compare periods `1:40`, not `.Data`.
- IRIS copies the data into the smoothed observables; `re_filter` checks the fit through `lhsmrhs` of the measurement equations (they are the first rows of its output).
- Timing: shares and beliefs used in t were computed at the end of t-1; BR agents see data up to t-1 (default `beliefs.info = 'lagged'`; `'current'` = period-t data as in IJCB eq. 12, toggle `br_info_current` in the generated file). The engine asserts every period that `x_exp1_BR` equals the PLM forecast with phi_{t-1} on that information set.
- Calibration (gain 0.0585, chi 0.51, omega 0.6, init n2 0.5) is set live in `config/master_options.m` and equals `hetlearn.defaults`, with sources there; chi = 0.51 is IJCB's estimate on quarterly data (user decision 2026-10-18; the old 8 = 0.51 x 16 assumed annualised IJCB data). Everything in `results/` and `reports/` made before 2026-10-18 used chi = 8.
- Projection facility (`projection.facility`, DESIGN 4.4) is the only stabilising device: `'plm_alm'` (default) keeps an explosive PLM block's beliefs, then checks the ALM; `'alm'` checks the ALM only; an unstable ALM reverts every belief to its pre-update value; if the shares alone make it unstable, last quarter's model shares stay in force too (`projection_alm_shares`; the discrete-choice `n1`/`n2` keep moving, `n1_model` records the kept share). `hetlearn:engine:almUnstable` is left only for initial beliefs and shares that are already unstable at the first check; `'none'` without a solution stops with `hetlearn:engine:noSolution`. Watch for runs that lean on kept shares: SW07 model-consistent all-12 under `'plm_alm'` keeps the origin's model shares in all 16 forecast quarters. The smoke helper reports a facility stop as an outcome, not a failure. Old option names (`projection.max_root`, `.on_failure`, `.method`, `.scope`, `switching.error_scale`, `.error_scale_ref`) raise `hetlearn:options:removed`, so round 1-2 scenario files that set them no longer run.
- `expectations.re_variant` defaults to `'anchored'` since 2026-10-18; set `'model_consistent'` explicitly where you want it (tests that check it pin it).
- SW07 covid quarters (user decision 2026-10-19): every observable is NaN in 2020Q1-2020Q3 (`covid_nan_quarters` in `models/sw07/data/build_database.m`). The RE filter skips them (fit check on quarters with data); the learners learn on the smoothed values there (on the filtered values, the RE prediction, under `history.re_states = 'filtered'`); `hetlearn.evaluate` drops those targets (3 per horizon and variable); the inversion has nothing to exogenise there, so from 2020 it no longer equals the RE smoother. `test_evaluate` V4 and `test_inversion` S1 were updated for this (S1 compares the shocks up to 2019Q4); both pass (2026-10-19). Without the covid quarters the AR(1) inflation PLM hits the facility in 2022Q1-2022Q2, so the beliefs in force at the 2022Q2 origin are those of 2021Q4.
- Anchored RE under Ramsey (open design question): anchored agents forecast with the RE solution under the Taylor rule, also in mode `'rational'`, so `a4_ramsey_*_re` are not RE Ramsey plans (balanced, 80 quarters: loss 38.9 vs 631.3 with `re_variant = 'model_consistent'`, which reproduces the round-2 RE Ramsey). Under the Taylor rule the two variants coincide (check C11). The model-consistent RE Ramsey plans are saved runs, `a4_ramsey_*_re_mc` (2026-10-19); `build_summary_v3.m` reads their losses and checks them against its own diagnostic (C12).
- The ALM check runs in the RE-smoothed history too (one solve per quarter; SW07 226 quarters: 3-10 s, `res.meta.history_alm_check_s`). `events.csv` has a `stage` column; `density_events.csv` columns are `draw,status,projection_plm,projection_alm,explosive_events,rls_missing,shares_nan,gain_bound,max_abs,message`.
- Scenario ids = scenario function names; `compare_with` and `'delta'` references to an id without results run that scenario first.
- In `res.learning`, `n1`/`n2` are the discrete-choice shares (diagnostic unless mode is `'switching'`); `n1_model` is the share actually in the model.
- Delete `models/<name>/generated/refilter_*.mat` only if you want to force a re-filter; the hash covers model text, parameters, database bytes and range.
- RE states of the history (`history.re_states`, 2026-10-19): `'smoothed'` (default, unchanged) or `'filtered'` (RE forecasts, learners' data and realised values in the fitness errors from the one-sided filter, x_{t|t}). The forecast still starts from the smoothed state; `'filtered'` + `history.realtime = true` is the fully real-time setup; `'filtered'` + `'inversion'` is an error. Every `refilter_*` cache now also holds `H.filtered`; caches written before 2026-10-19 are re-filtered and rewritten in place on first read (same name, same smoothed history), so run one session before parallel ones that share caches.
- RE information set (`expectations.re_info`, 2026-10-19; DESIGN 19): `'current'` (default, unchanged) or `'lagged'`: the RE expectations of the learning set are E_{t-1} x_{t+1}, the RE counterpart of `beliefs.info = 'lagged'`. Everything RE in such a scenario uses the RE(t-1) model of its learning set (RE benchmark, anchored forecast, RE filter, f^RE, RE-moment initial beliefs), so compare a lagged learning run with a lagged RE run, not with `a1_re`. Separate generated file `<name>_ext_<tag>_relag.model` (generator version 5; the default files stay at version 4, byte-identical) and separate RE filter caches (they also hold `H.predicted`; under `'filtered'` f^RE is the filter's two-step prediction). The anchored lagged forecast solves out the RE agents' own lagged forecast (fixed point; the alternative mapping to the aggregate expectation is written up in DESIGN 19 for the user to decide). Errors: an empty learning set, Ramsey policy, learning variables with leads of 2 or more.

- Runtimes (SW07, 2026-10-18): a scenario 3-25 s; a 500-draw learning density 6.5 min in one run (0.71 s per draw;
  RE densities use the fast path, about 30 s); the evaluation 2.7 hours of compute (10 variants x 138 origins), about
  47 min with 4 parallel sessions (`run_applications('eval_part', ...)`, then `'eval_merge'`).
- Parallel batch sessions are safe once the model caches exist and every `compare_with` target has results: a missing
  target is run first, so two sessions can write the same `results/<id>/`.
- MATLAB `-batch` does not start in the PowerShell working directory: `cd` to the project root first. With
  `Start-Process`, quote the whole `-batch` command (the OneDrive path has spaces).
- `engine.step` defaults to `'fast'` (equal to `'iris'` to about 1e-12, 2-3x faster, 20x with observables exogenised).
- The inversion history is real time by construction (period t uses data up to t). A PLM on a variable an observable
  pins down (SW07: pinf, c, inve, w, lab) gets the same beliefs under the inversion as on the RE-smoothed history; the
  RE forecasts, hence the shares, and the shocks change.
- Evaluation parts must partition the origins (`run_applications('eval_merge')` checks); the merge uses
  `hetlearn.evaluate_tables`. Real-time filter caches (`refilter_rt_*`) are per PLM spec and RE variant.
- Model packages take published parameter values only; nothing is estimated (user rule, 2026-10-18).
- The repository (`.gitignore`) excludes `results/` (except the summary scripts and the memo), `**/generated/`,
  `tests/output/`, `reports/*.html` and `archive/`.
